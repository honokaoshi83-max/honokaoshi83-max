# 自动赛后复盘

本次为本地测试更新，尚未同步 GitHub 或重新制作安装包。

## 保存和查看

- 左侧“复盘”以表格展示最近一次已保存的比赛，包含比赛信息、圈速与稳定性、正赛排名和完整评价。点击“查看复盘文本”在资源管理器中选中对应 TXT。历史文件仍全部保留。
- 文件位于应用程序目录的 `复盘` 文件夹；同名 JSON 保存索引和统计数据。
- 保存成功后，由芙宁娜播报一次“本次复盘已经保存。”。取消原先询问是否保存的语音。
- 保存失败不会播报成功，会记录错误并重试；重启后不会重复保存已完成的记录。
- 更新程序保护个人复盘、会话状态和日志，不将它们当作公共程序文件覆盖。

## 正赛

本地根据已记录的比赛数据自动生成详细评语，不依赖 AI API。Simulator Controller 原有的赛后语音保持原样；详细评语只写入文本和页面。原生评价未生成时，会话结束等待约 30 秒后仍保存本地复盘。取消资格时明确记录，不使用完赛排名措辞；没有完整圈速时说明数据不足。

补充总排名、组别排名、参赛车辆数，以及有数据时的发车名次和名次变化。最终结果尚未发布时，标注为 SDK 最后观测值，避免当作正式成绩。

## Time Trial

仅适用于 Time Trial，不改变练习和排位。至少记录两个完成圈后生成评价；排除出场圈和进站圈。

- 有效圈：分析最快圈、平均圈速；有效圈足够时比较前后段节奏。
- 稳定性：包含有用时的犯规无效圈；无用时的无效圈也计入无效比例，不编造用时。
- 不分析排名，不包含燃油、轮胎分析，也不冒充 iRacing 官方连续圈评分。
- 圈速波动率＝计时圈用时的总体标准差÷平均圈速×100%。不超过0.75%为稳定，超过0.75%且不超过2%为有一定波动，超过2%为不稳定；不足五个计时圈只显示数值、不评级。比例显示两位小数，分档使用未舍入值。
- 文本把简短规则放在波动率后面的括号中：“（0.75%内为稳定；0.75%至2%为有一定波动；超过2%为不稳定）”。删除评价末尾的长段说明；完整公式和精确边界保留于JSON规则元数据及本文。括号说明不进入语音。
- 全部计时圈（含有用时的犯规圈）与有效计时圈分别计算。犯规比例和连续有效圈另行说明；取消“出现无效圈自动降级”，缺失用时的无效圈只计入犯规比例。评价段落记录百分比与括号分档；JSON保留完整公式和规则版本，历史文件不自动改写。
- 慢圈用有效圈的中位数和MAD辅助识别：慢于中位数的幅度超过 `max(3.5×MAD/0.6745, 0.1秒, 中位圈速×0.75%)` 时单独说明。至多20%的有效圈符合时称为“个别”，否则称为“部分”；全部保留在统计中，不推断原因，也不据此抬高评级。
- Time Trial 语音和文字共用波动率、分档与最低样本规则。语音播报百分比和结果，简短括号规则显示于文本和页面，不朗读规则。

### 方法参考

- [Ken Hill / Blayze的圈速重复性训练](https://blayze.io/blog/car-racing/what-to-work-on-next-for-on-track-improvement)：参考连续复现圈速的训练思路；文中0.3～0.5秒是训练目标，不直接当作通用标准差阈值。
- [NIST：离散程度与MAD](https://itl.nist.gov/div898/handbook/eda/section3/eda356.htm)、[潜在异常值识别](https://itl.nist.gov/div898/handbook/eda/section3/eda35h.htm)：用于辅助描述个别慢圈。0.75%/2%、五圈门槛、慢圈检测下限和20%称谓范围都是助手自定参数，不是官方赛事评分。

## 详细评语与页面

- 页面按当前窗口高度分配空间，不使用整页纵向滚动。表格每行三组“项目／数据”。评价栏初始与上方数据区约为 1∶5，按实际文字换行高度自动扩大，最大为 2∶3；文字缩短和窗口尺寸变化时重新调整。
- 评价以紧凑段落排列，可选中文本。超出评价区域的内容可在框内滚动，或定位到完整 TXT。
- 评语包含比赛结果、有效圈速、前后段变化、稳定性、最长连续有效圈、犯规比例，以及下一场重点。只输出有依据的内容。
- 最快圈、有效平均圈只使用有效计时圈；稳定性包含犯规无效计时圈，无用时无效圈仍计入犯规比例。
- 至少四个有效计时圈才比较前后段，使用等量样本，变化阈值为 0.1 秒与有效平均圈速 0.2% 中的较大值。
- 前后段趋势只比较两段平均值；单圈稳定性比较各圈离散程度。两段平均值接近不代表每圈用时接近，文本分别说明这两个指标。
- 缺失圈数或犯规会打断连续有效圈计数；这个统计不是 iRacing 官方 Time Trial 连续圈成绩。
- 不从圈速变化推断疲劳、轮胎、燃油、事故责任或驾驶动作。正赛未取得正式排名时使用“最后记录”措辞；中途接入明确标注仅评价记录时段。
- 同一条复盘的表达保持一致。后续新比赛使用新数据独立生成，不自动改写旧文件。
- 退出后重连相同赛事时继续采集；先前已保存的退出快照保留，最终生成新的复盘并记录前一份标识。缺口期间不补造圈速，记录用时扣除该缺口。
- Time Trial 语音保留原有简短总结；更详细的内容只进入文本和页面。

## 文本信息

记录本机真实起止日期与时间（含时区）、赛道及布局、车辆、模式、完成圈数和评价。完整观测比赛起止边界时记录 SDK 总用时；中途接入则注明总用时未知，另列已记录用时。

## 提前退出后的复盘

- SDK 提供有效的 `SessionTimeRemain` 时，按最后一次剩余时间保存预计结束时刻。提前退出不立即生成复盘，到预计结束后再分析。
- 例如三十分钟的 Time Trial 跑二十分钟退出，再等待约十分钟；仅分析已记录的二十分钟和完成圈。
- 等待状态落盘，重启助手或进入其他会话仍保留。截止前重连同一场会继续采集，不另建一份重复复盘；游戏内明确确认结束时可以解除等待。
- 断连后的实际结束时刻、后续圈速和正式排名不可通过本地 SDK 确认。文本明确标注预计结束时间的依据；不将退出前名次当作最终排名，也不将预计时长当作实际比赛总用时。
- 需要助手后台运行；如果后台已关闭，下一次启动时检查到截止时间已过，再生成复盘。此功能不查询 iRacing 网页赛事结果。
- 无剩余时间或无限时／异常值时，无法安排可靠的结束时刻，保留原有退出快照处理，并明确结束时间未知。

## 验证边界

已覆盖保存失败重试、重启去重、最近一次展示、文件定位、角色路由、成绩先于圈数更新、相同圈速发布确认、短时断连及模拟器仍运行时的断连、出场圈计数复用、无计时无效圈、无原生评价的正赛回退、详细评语与简短语音分离等自动回归。

游戏内完整正赛和 Time Trial 的结束时机、最终结果发布、犯规样本及实际听感留给用户验收。原有圈速触发器不改动。
