# 双音色缓存与自动恢复

更新：2026-10-12。工程师为克洛琳德，观察员与策略师为芙宁娜。

## 缓存

已生成当前部署中文语法中的固定表达及直接遥测损伤提醒，共190个音色、短句、格式组合。读取安装版语法并用用户语法覆盖，包括独立的过车/旗号语法区段；同文同音色同格式去重。

Simulator Controller 使用的固定语句缓存MP3；直接遥测损伤与维修提示缓存WAV。缓存保存在原有cache目录，重启后继续使用。动态圈速、具体油量、赛道名称或带数值的复合语句仍可能需要实时合成，不能据此保证所有播报即时返回。

重新补齐缓存：在项目根目录运行（不播放音频）：

```powershell
.\.runtime\python\python.exe -X utf8 .\work\race-voices\warm_cache.py
```

如果发现游戏连接，缓存任务会在当前请求结束后暂停，避免持续与驾驶播报争用合成引擎。已生成文件保留，离开游戏后重新运行可复用。

## 自动恢复

正常启动脚本已接入隐藏后台监督进程，不需要另开窗口。每2秒检查本项目语音服务和遥测进程。连续3次异常后尝试恢复，重复失败按5、10、20、40、60秒退避，最长60秒。稳定恢复后重置退避。

- 语音进程退出、语音健康接口持续失败：恢复本项目语音进程。
- 遥测进程退出：恢复遥测进程。
- 9881端口被其他程序占用：记录冲突并等待，不结束对方进程。
- 手动运行scripts/stop.ps1：先停止监督进程，关闭服务后不会自动拉起。
- 重复运行scripts/start.ps1：复用现有服务；监督进程还有系统文件锁防止重复运行。
- 恢复与故障状态仅写入本地记录，不主动合成错误提示。直接遥测音频错误按中断周期去重记录。

当前自动恢复针对本地进程和健康接口；不处理DeepSeek云端API故障，不代表已经解决Simulator Controller内部所有错误提示，也不检测健康接口仍正常时的模型推理卡死。进程重建会丢失内存中的模型状态，未缓存的新句可能承担冷启动时间。

状态文件：work/race-voices/watchdog_status.json。事件记录：work/race-voices/watchdog_events.jsonl。监督进程随项目启动，不单独设置Windows开机自启。
