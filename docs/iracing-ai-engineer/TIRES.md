# 轮胎检查与播报

2026-10-12。赛事工程师克洛琳德播报；不自动操作换胎选项或修改赛车设置。

## 检查内容

| 项目 | 数据与提醒条件 |
| --- | --- |
| 冷胎压设置 | LFcoldPressure等四轮设置值持续2秒越过检查上下限。播报明确说“冷胎压设置”，不称为实时胎压。 |
| 实测胎压 | 只有共享遥测确实提供LFpressure等字段且单位明确时启用；先转换为kPa。观察到进站附近数据变化、停车并稳定2秒后检查。缺失字段时不使用下次进站目标胎压冒充实测值。 |
| 胎温 | 使用LFtempCL/CM/CR等胎体温度，检查三处读数的最高值和整体低温。只分析本模块观察到的进站附近刷新，不把旧值当成当前胎温。低温提醒须已完成至少2圈，识别到换上新胎时抑制该次低温提醒。 |
| 磨损 | 使用LFwearL/M/R等三处剩余胎纹比例，以最薄处判断，不把“剩余70%”理解为“磨损70%”。只分析进站附近刷新的读数。 |

提醒示例：

- “冷胎压设置低于当前检查下限，请检查胎压设置。”
- “进站更新的胎温高于当前检查上限，请检查轮胎负荷和驾驶方式。”
- “进站更新的胎纹余量较低，请确认换胎安排。”
- “进站更新的胎纹余量已达到严重磨损提醒线，请确认已经换胎。”

同一指标、同一级别提醒去重；磨损升级可再次提醒，观察到新的正常读数后允许再次触发。相同异常的多个车轮合并为一条短句，具体车轮和读数写入本地记录。

## 初始检查线

这些是本项目的可调检查阈值，不是iRacing官方推荐的最佳工作范围。不同车型、轮胎配方、干湿地与驾驶方式需要复核，当前没有完成车型专属阈值标定。

| 配置 | 初始值 |
| --- | --- |
| 胎压检查范围 | 110–350 kPa |
| 胎温检查范围 | 40–130℃ |
| 胎纹余量提醒线 | 最薄处剩余≤70% |
| 严重磨损提醒线 | 最薄处剩余≤40% |
| 读数稳定时间 | 2秒 |
| 低温检查最少圈数 | 2圈 |

配置在work/race-voices/tire_settings.json。defaults为默认阈值，cars可以按SDK提供的CarPath覆盖单项。修改后重新加载遥测进程或开启新会话读取。下限高于上限、无效磨损比例等配置错误会记录并回退默认值，避免影响其他播报。

## 数据边界

iRacing官方说明，F6轮胎温度与磨损通常在进站更新，可能是刚换下轮胎的记录。这里说“进站更新”以区分历史测量与实时状态；提醒不是对新装轮胎仍然磨损的判断。

- 初始化、回放、未上车、缺失字段、NaN/无穷值和无效数值不触发。
- 中途接入时建立基准，不立刻播报之前残留的异常读数。
- 没有观察到数据变化时保持安静；真实数值完全未变化的更新可能因此不触发，这是保守取舍。
- 当前不会读取画面或从圈速猜测胎温、轮胎磨损，不承诺爆胎判断。
- 未暴露实测胎压时只能检查冷胎压设置，不能实现实时热胎压或慢漏气监控。

状态：work/race-voices/tire_monitor_status.json，连接游戏后记录车型、字段能力、最新读数与阈值。当前尚未连接游戏，具体车辆字段能力与游戏触发仍待验收。

## 验证与缓存

轮胎规则新增14项检查，轮胎功能完成时累计59项自动检查通过；当前项目累计70项通过。覆盖进站刷新、旧数据抑制、每轮每指标的新鲜度、单位转换、热胎门槛、剩余胎纹判断、分级去重、新胎恢复、缺失与全零初始化。另修正语速1与1.0的缓存键，使省略语速与显式语速1的请求共用已有缓存。

8条轮胎固定提示采用克洛琳德WAV缓存，与已有缓存一起维护。实际语音接口验证记录见“轮胎检测验证.json”（本机验证记录）。游戏内验收由用户之后进行。
