## 新发现：干净安装后组件自动启动被前置检查阻止

状态：**已在临时目录复现，尚未修复。当前本机不受影响。**

一键安装函数`prepare_config`和语音接入函数可以在全新用户目录中建立基础配置和中文语法；`inspect_simulator`随后判断为“已配置、已接入”。但该路径没有建立`Config/ID`。

本地新增的150米慢车范围准备逻辑依赖这个ID。`SimulatorLink.ensure(True)`在ID缺失时返回`needs_database_identity`，不会启动组件。因此，全新设备若没有先运行组件完成自身初始化，可能出现界面显示接入成功、自动启动却停住的情况。

临时目录复现结果：

```json
{
  "configured": true,
  "integrated": true,
  "identity_exists": false,
  "automatic_start_result": "needs_database_identity",
  "controller_launched": false
}
```

应补齐初始化与重新检测流程，并保持150米限制和已有用户身份不变；再新增覆盖“一键安装到首次自动启动”的组合回归。现有单元测试分别验证安装成功、缺ID时不按500米默认启动，两者都通过，但没有覆盖组合后的可用性。

该前置检查属于10月15日本地修改，未纳入已发布0.2.4安装包；不据此认定旧安装包存在同一原因的问题。本轮未重新进行真实卸载安装或另一台设备安装。
