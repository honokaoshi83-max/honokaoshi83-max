# 赛前策略模块设计

状态：完整功能设计。第一阶段页面、离线燃油预案与本地保存已接入；实时动态策略执行仍待开发。具体记录见 ../plans/2026-10-15-strategy-page.md。

2026-10-15 用户补充：栏目标记“测试中”；策略模块必须手动开启，未开启时不计算、不跟踪、不产生策略播报。首次及每次启动默认关闭。关闭模块不影响原有基础播报。

## 目标与范围

为现有应用增加与“运行概览”“音色管理”“诊断日志”平级的“赛事策略”入口。用户在进入游戏前填写赛事、车辆和燃油条件，生成初步燃油计划；进入会话后核对实际信息，并根据有效跑圈数据修正进站窗口与补油建议。

典型场景：纽博格林四小时耐力赛。必须选择具体布局，不能仅用“纽博格林”推断圈长。

第一版只规划、显示和提醒，不操作游戏加油设置。事故后重算纳入设计；没有维修时间时不编造维修耗时。天气换胎策略、驾驶员轮换、对手预测和自动设置进站服务留作后续功能。

## 设计选择

可采用向导、单页表单或独立赛事面板。推荐独立赛事面板：左侧填写条件，右侧预览策略，下方查看进站计划与执行变化；赛中不需要反复进入向导。

沿用现有蓝白配色、背景、圆角卡片和侧栏宽度，不增加新人物图片，不重排首页。导航顺序：运行概览 / 赛事策略 / 音色管理 / 诊断日志。

## 输入与校验

| 字段 | 交互与用途 |
|---|---|
| 赛事名称 | 用户命名，例如“纽博格林四小时”；名称不参与时长计算 |
| 赛道及布局 | 支持搜索选择；未知赛道可手动录入，进入游戏后核对标识 |
| 车辆 | 搜索选择；历史油耗按车辆与赛道布局分别存储 |
| 比赛长度 | 限时 / 限圈二选一，默认限时四小时；允许分别编辑 |
| 初始燃油 | 升；由用户在游戏内设置，连接后显示实际油量并核对 |
| 本场油量上限 | 升；计算多段加油必须提供。优先展示已确认的数据来源，无法读取时手填，不能假定为车辆标称容量 |
| 预计圈速 | 分、秒、小数分栏，避免“8.30”歧义；可引用历史记录并显示日期与样本数 |
| 单圈油耗 | 升/圈；可手填或引用同车同布局的历史有效圈 |
| 安全储备 | 以“圈”为单位输入，可设小数；首次默认一圈，可编辑，作为计算余量而不是额外重复扣减 |
| 提醒设置 | 默认启用进站窗口、油量紧张和计划变化提醒；放在可展开区域 |

初始油量、时长、圈速、油耗必须为有效正数；初始油量不得超过本场油量上限。无法生成的字段给出就地提示。

允许在缺少油耗或圈速时保存草稿；不得生成看似精确的进站表。缺少油量上限时可以显示当前续航，但不显示完整进站次数。没有可靠进站损失时，不给出精确比赛总用油或节油收益承诺。

首版不依赖新增联网查询获取车辆参数，使用现有本地名称目录及用户输入。

## 策略结果

显示预计比赛圈数范围、进站次数、首停窗口、建议补油量、安全储备和计算依据。未开始比赛用相对比赛时间或预测圈次；开始后再结合真实赛程显示，不能把系统时钟直接当作比赛时间。

进站表字段：停次、预计进站时段/圈次、建议补油（增加多少升）、预计出站油量、状态。首次生成是预案，进入游戏后持续修正。存在不确定性时用范围，不伪造秒级精度。

“建议补油”始终指增加的油量；“预计出站油量”指加完后的总量。两者不混用。计划建议与实际黑盒中“当前进站服务”分别展示。

## 游戏内跟踪流程

1. 保存并生成预案，用户选择“用于本场比赛”。同一时间只启用一份策略。
2. 连接后核对赛道布局、车辆、会话类型、比赛长度与油量。车库、练习和排位可以采样，不启动正赛倒计时。
3. 赛道、车辆或赛事长度不同，标记“待确认”并停止使用旧计划给出本场建议；提供“采用游戏数据重算”和“保留草稿”。不得静默改写用户预案。
4. 初始油量在开赛前或首次可靠观测时核对；已开始驾驶时只按实际剩余油量修正，不把途中消耗误报为初始油量不一致。
5. 使用干净完整圈建立油耗；出场圈、进站圈、加油跨界、遥测断开、圈数跳变等不进入正常样本。允许提示事故圈，但排除其对正常基准的明显污染。
6. 至少两个有效完整圈后形成首个实测基准，随后取最近五个有效圈，并显示数据是否仍不足或已过时。圈速与油耗分别维护有效性。
7. 每圈完成、加油、维修时间变化、赛事条件变化时更新计划；内部计算可以频繁刷新，语音只在重要变化时触发。
8. 暂停策略提醒只停止本模块语音，原有旗号、邻车、圈速和车辆告警继续工作。
9. 断开时显示最后更新时间和“连接中断”，停止使用过期数据触发新建议；同场重连重新核对，换场后不沿用旧执行状态。

## 计算原则

- 限圈赛使用真实剩余赛程，明确是否包含当前未完成圈；不能把 SDK 的圈数值直接无条件加一。
- 限时赛使用剩余时间与有效圈速估算，考虑当前圈进度及计时结束后的完赛规则，输出范围并预留安全储备。具体 SDK 字段语义须在实现前用录制数据核对。
- 当前圈剩余燃油需求与后续完整圈需求分开计算，长赛道尤其不能等到下一次过线才发现无法到站。
- 燃油安全储备只计一次。容量限制、加油上限、维修耗时和进站消耗必须单独处理。
- 无进站损失数据时先做保守预案，显示假设；实测进站损失后重新预测可完成圈数。限时赛维修耗时可能减少最终可完成圈数。
- 预计能跑到终点时只建议满足完赛和储备所需的油量，不默认最后一停加满。
- 油量/圈速异常或样本不足时退回已知来源并明确标注，不能使用无标记的通用油耗。

## 事故与维修后的调整

收到可靠维修告警后提示事故及进站需求，复用现有车辆告警，不增加具体损坏部位猜测。

维修时间未知时保留原计划并标记待重算；实际维修时间可用后，重新计算剩余赛程、建议补油和后续停次。区分“事故进站建议”与已确认进入维修位，不因一个告警就把计划中的进站标记为完成。

维修结束或加油完成时，根据实际油量重新建立当前赛段边界。正常油耗基准可保留供参考，事故后新样本用于检查持续损伤造成的耗油变化。

## 播报与角色

保持已确认职责：策略主动提醒由芙宁娜负责；车辆维修告警与按键完整摘要由克洛琳德负责，按键摘要可引用同一份策略结果。

| 情况 | 文本示例 |
|---|---|
| 实测校准导致实质变化 | 按当前油耗，首停需要提前一圈。 |
| 接近进站窗口 | 建议两圈后进站。 |
| 推荐进站圈 | 本圈进站，建议补油三十二升。 |
| 燃油可完赛 | 油量够到终点。 |
| 维修导致计划变化 | 维修后重新计算，后续还需一次加油。 |

提醒以事件键去重，跨圈重复遵循明确的升级规则；不因数值微小抖动连续播报。策略语音进入现有统一队列，不建立第二个播放器，不抢占开场介绍；紧急旗号与邻车提醒优先。

## 数据与工程边界

建议独立 strategy 模块：计划存储、计算、执行跟踪、事件生成与页面组件分离；页面不直接调用语音模型。由后台持有同一份执行状态，关界面保留后台时策略仍能运行，避免 UI 与按键摘要各算一份。

计划保存在用户可写配置目录，带 schema_version；预案、执行快照、历史采样分开保存。升级补丁保护策略个人文件，不覆盖用户计划。写入失败保留旧文件并提示。

现有 0.2.6 更新功能、角色路由、圈速边界识别、固定缓存和按键设置不改动。新增后必须做相应回归核对。

## 验收安排

自动检查：缺少数据、错误单位、油箱限制、长圈中途续航、限圈/限时、当前圈进度、最后一停、余量只计一次、出场圈污染、加油重置、事故维修重算、重连换场、事件去重及音色路由。

界面检查：新增一级入口、原页面顺序映射正确、窄窗口滚动、草稿保存恢复、待确认状态、缺失字段提示、后台运行时策略连续性。

实际游戏留给用户：纽博格林长圈、限时结束边界、真实加油量和比赛油量限制、维修倒计时、播报时机、按键摘要一致性。

本设计没有宣称已完成游戏接口接入，也不修改当前安装包或 GitHub。下一步经页面与规则确认后，再编写实施计划并开发。
